Wrangl: Agent Hierarchy

Wrangl is a Claude Code plugin that gives your session a team. Your session takes the lead and hands work to other Claude Code sessions, which design it, build it and review it. A small program on your machine, ahd, carries the messages between them, and ah is the command you and the team use to run it all.

Wrangl is new and still being tested. It starts other agent sessions that edit files and run commands in your repository, so only point it at work you have committed or backed up. You will hit bugs, and commands, settings and screens may change between releases. It comes with no warranty (see the LICENSE). If something breaks, please open an issue at github.com/agentic-tool-labs/wrangl/issues.

What you get

A team from one session

Your session becomes the Chief Orchestrator. It splits a job up and passes each piece to the right specialist. Every role can run on its own model, so you can spend a strong model on design and a cheap one on running builds and reading logs.

Architect
writes the design (a “spec” file)
Implementor
builds exactly what the spec says
Reviewer
checks the work against the spec
QA
runs the heavy test suites and reports failures
Ultra-Advisor
settles the hardest calls
Docs-Writer
writes READMEs, guides and changelogs
UX-Engineer
builds web UI and checks it in screenshots
Sub-Orchestrator
runs one separate line of work (a “lane”)
Task-Runner
runs builds, searches the code and reads logs
Backlog-Groomer
sorts and ranks the backlog, and closes what is already done

The team, and what each role never does

A daemon that carries the mail

ahd runs in the background on your machine, one copy per user. A team can work without it, since teams, messages and the roster are plain files, but you need it for timers, wake-ups, message delivery, links between teammates and the terminal view.

Wrangl also keeps each member writing only inside its own work area, tells you when someone is stuck, and brings the team back after a crash or a reboot.

The daemon

Three ways to watch

  • The web page shows the whole team at once, and only your machine can open it. Start it with ahd ui.
  • The terminal view, ahd tui, fits in a pane beside Claude Code and works over SSH.
  • Herdr desktop puts the team in the app's sidebar.

Install

You need Claude Code 2.1.289 or later, a .NET 10 SDK (the installer offers to install one) and a C toolchain, on macOS or Linux. If you have the older ah plugin (v1), turn it off first: see Wrangl and ah v1. Then, in a terminal:

curl -fsSL https://raw.githubusercontent.com/agentic-tool-labs/wrangl/main/install.sh | bash

It shows you its plan and asks before it changes anything. If you would rather read a script before you pipe it into bash, Install with one command shows how. Or do it by hand, inside Claude Code:

/plugin marketplace add agentic-tool-labs/wrangl
/plugin install wrangl@wrangl
/wrangl:hierarchy install

Turn it on with /wrangl:hierarchy init, then /clear. Check it in a terminal with ah roster doctor --brief: no line should start with red. The full install guide covers every step and how to uninstall.

Quick start, in about ten minutes

  1. Turn the hierarchy on. Run /wrangl:hierarchy init once, choose user or project, then run /clear or start a new session.
  2. Pick your team. With no roster yet, init hands you on to the /wrangl:agent-roster wizard, which asks which roles you want and which model each runs.
  3. Start the team. Just ask: "set up my team".
  4. Say what the team is for (optional). Give the Orchestrator the goal in a sentence, such as "our goal is a working login page". Every member sees it.
  5. Give the Orchestrator a job. Describe the change you want. It does small jobs itself and passes bigger ones to the Architect, the Implementor and the Reviewer.
  6. Check on the team at any time with ah roster teams and ah roster status --plain.
  7. Wrap up. When the work is merged, ask the Orchestrator to wrap up the stream and dismiss the team.
