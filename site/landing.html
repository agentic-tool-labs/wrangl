Wrangl: Agent Hierarchy

A Claude Code plugin that turns one Claude Code session into a small software team, coordinated by a local daemon. Its commands are ah and ahd.

Early testing: use with caution. Wrangl 2.0.0 is an early public release and is still being tested. It starts and controls other agent sessions that edit files and run commands in your repository, so use it only on work you have committed or backed up. Expect bugs, and expect commands, settings and screens to change between releases. Wrangl is provided “as is”, without warranties of any kind; see the LICENSE. Report problems at github.com/agentic-tool-labs/wrangl/issues.

Get started How it works

What you get

A team from one session

Your session becomes the Chief Orchestrator. It breaks a job into pieces and hands each piece to a specialist. Each specialist runs on the model that suits its job, so design gets a strong model and routine legwork gets a cheap one.

Architect
writes the design (a “spec” file)
Implementor
builds exactly what the spec says
Reviewer
checks the work against the spec
QA
runs the heavy test suites and reports failures
Ultra-Advisor
settles the hardest calls
Docs-Writer
writes READMEs, guides and changelogs
UX-Engineer
builds web UI and proves it with screenshots
Sub-Orchestrator
runs one separate line of work (a “lane”)
Task-Runner
cheap legwork: run builds, search, read logs
Backlog-Groomer
triage, ranking, dedupe, proven-done items

The team, and what each role never does

A daemon that carries the mail

ahd is a small background program that runs on your machine, once per user. Teams, message files and the roster work from plain files without it; timers, wake-ups, the delivery ladder, links between teammates and the terminal view need it.

Around the team, Wrangl passes messages between members, keeps them from writing outside their own work area, tells you when someone is stuck, and brings the team back after a crash or reboot.

The daemon

Three ways to watch

  • The web page: your whole team at once, on your machine only. Open it with ahd ui.
  • The terminal view: ahd tui, for a second pane beside Claude Code or over SSH.
  • Herdr desktop: the team sitrep in the Herdr desktop app’s sidebar.

Install

You need Claude Code 2.1.289 or later, a .NET 10 SDK (the installer offers to install one) and a C toolchain, on macOS or Linux. If you have the older ah plugin (v1), turn it off first: see Wrangl and ah v1. Then, in a terminal:

curl -fsSL https://raw.githubusercontent.com/agentic-tool-labs/wrangl/main/install.sh | bash

It shows its plan and asks before it changes anything. Piping a script into bash runs code you have not read; to read it first, see Install with one command. Or do it by hand, inside Claude Code:

/plugin marketplace add agentic-tool-labs/wrangl
/plugin install wrangl@wrangl
/wrangl:hierarchy install

Turn it on with /wrangl:hierarchy init, then /clear. Check it in a terminal with ah roster doctor --brief: no line should start with red. The full install guide covers every step and how to uninstall.

Quick start, in about ten minutes

  1. Turn the hierarchy on. Run /wrangl:hierarchy init once, choose user or project, then run /clear or start a new session.
  2. Pick your team. With no roster yet, init hands you on to the /wrangl:agent-roster wizard, which asks which roles you want and which model each runs.
  3. Start the team. Ask in plain words: “set up my team”.
  4. Say what the team is for (optional). Tell the Orchestrator the goal in one sentence, for example “our goal is a working login page”. Every member sees it.
  5. Give the Orchestrator a job. Describe the change you want. A small one it does itself; a bigger one goes to the Architect, the Implementor and the Reviewer.
  6. Check on the team at any time with ah roster teams and ah roster status --plain.
  7. Wrap up. When the work is merged, ask the Orchestrator to wrap up the stream and dismiss the team.
